# Архитектура ScreenMirror RU

Статус: проектирование следующего этапа. Текущий TCP/H.264 прототип остаётся контрольной точкой и не удаляется.

## Цель

Передавать экран Android-телефона на Android TV по локальной сети без обязательного облака, компьютера или платной подписки. Основные сценарии: быстрое сопряжение, стабильное видео, корректное вписывание кадра в экран ТВ, звук там, где Android разрешает его захват.

## Что показало сравнение проектов

- **scrcpy (Apache-2.0)** — эталон по MediaProjection/MediaCodec, задержкам, управлению кодеками и диагностике. Это не готовый Android TV receiver, поэтому переносить проект целиком нецелесообразно.
- **TV-Bridge (MIT)** — близкий по сценарию пример WebRTC, QR и Android sender/TV receiver. Репозиторий молодой; его сервер сигнализации требует отдельный Node.js-хост, а аудиомост использует хрупкую рефлексию во внутренние поля WebRTC. Эти решения не копируем.
- **AndroidScreenCaster** — полезный пример захвата и настройки аппаратного H.264/VP8 кодирования.
- **screen-mirror-android** — идеи NSD/mDNS обнаружения, но не готовая основа для переноса без дополнительной проверки лицензии и зрелости.
- **android-airplay-server** — дополнительный источник идей по TV-декодированию и аудиоформатам, но AirPlay не является протоколом нашего sender.

## Предлагаемая схема

1. **Обнаружение:** Android NSD/mDNS в локальной сети. ТВ публикует сервис ScreenMirror RU, телефон ищет его автоматически.
2. **Сопряжение:** QR-код с адресом/портом ТВ и одноразовым токеном сессии. Ручной ввод IP остаётся запасным вариантом.
3. **Сигнализация:** локальное соединение телефон ↔ ТВ для обмена SDP/ICE. Не отправлять медиапоток через сигнализационный сервер.
4. **Медиа:** WebRTC peer-to-peer по LAN. Начальный приоритет — H.264 для совместимости; кодеки и аппаратные возможности проверяются на обоих устройствах. VP8 — возможный запасной вариант. Не обещать HEVC, пока не проверена сквозная поддержка.
5. **Видео:** MediaProjection → WebRTC video source/capturer → аппаратное кодирование → WebRTC → аппаратное декодирование ТВ. Начальный профиль — адаптивный 720p/30; 1080p и 60 fps включать только после проверки возможностей и пропускной способности.
6. **Звук:** отдельный переключатель. AudioPlaybackCapture доступен начиная с Android 10 при разрешении пользователя, но приложения могут запрещать захват; защищённый контент и некоторые системные звуки могут отсутствовать. При невозможности захвата приложение продолжает трансляцию видео без звука. Не использовать reflection в приватные поля WebRTC.
7. **Отображение:** по умолчанию aspect-fit без обрезки; дополнительный режим заполнения экрана может обрезать края и должен быть явно обозначен.
8. **Локальная работа:** базовый сценарий должен работать в одной Wi-Fi/LAN-сети без обязательного интернета и внешнего signaling-сервера. STUN/TURN — только необязательный fallback, если позже понадобится работа через разные сети.

## Ограничения Android

- MediaProjection требует явного системного согласия пользователя. На новых Android согласие запрашивается для каждой сессии; один экземпляр MediaProjection нельзя повторно использовать для создания нескольких VirtualDisplay.
- Нужно регистрировать MediaProjection.Callback и освобождать ресурсы при onStop, отключении клиента и уничтожении поверхности.
- AudioPlaybackCapture зависит от версии Android, разрешения RECORD_AUDIO, MediaProjection и политики захвата исходного приложения.
- Реальное качество зависит от кодеков, разрешений, Wi-Fi, прошивки ТВ и фоновых ограничений производителя.

## Лицензии и заимствование

Использовать только собственную реализацию и небольшие фрагменты с проверенной совместимой лицензией и сохранением требуемых уведомлений. Для scrcpy учитывать Apache-2.0; для TV-Bridge — MIT. Не копировать проект целиком и не переносить рефлексивный аудиомост. Перед включением любой сторонней библиотеки фиксировать версию, лицензию и транзитивные зависимости.

## Критерии готовности

- Сопряжение без ручного поиска IP (QR и автообнаружение).
- Видео устойчиво восстанавливается после отключения/повторного подключения.
- Кадр не обрезается в режиме «Вписать».
- Видео работает без интернета в одной локальной сети.
- Отсутствие разрешения/возможности захвата звука не ломает видео.
- Оба APK собираются в CI; фактическая совместимость подтверждена отдельным тестом на телефоне и Android TV.
